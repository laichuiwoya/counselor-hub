# 数据库初始化

本目录只保留当前六表版本的两个 SQL 文件。数据库为 `counselor_db_v2`，要求 MySQL 8.0.16+。

| 文件 | 用途 |
| --- | --- |
| `01_schema.sql` | 删除并重建六张表，包含索引、关联约束及学生逻辑删除字段 |
| `02_demo_data.sql` | 清空六表数据，插入一套全新的虚构演示数据，操作日志保持为空 |

执行前停止系统并备份数据库。**两个脚本都会清除现有数据。**

## 执行顺序

在 MySQL 客户端依次打开并执行 `01_schema.sql`、`02_demo_data.sql`，然后启动系统。

表结构已经是当前版本、只想重置数据时，单独执行 `02_demo_data.sql` 即可。数据脚本按关联顺序清空和插入，重复执行不会堆积演示数据。数据库名称写在脚本开头；使用其他库名时应同时修改两个文件和应用连接配置。

## 演示数据

| 内容 | 数量 |
| --- | ---: |
| 系统用户 | 4 |
| 学生 | 24 |
| 学生记录 | 40（奖惩、请假、资助、档案、就业各 8 条） |
| 工作记录 | 16（工作提醒 10 条、纪要 6 条） |
| 访客 | 8 |
| 操作日志 | 0 |

账号：`admin`（管理员）、`chenlaoshi`、`zhoulaoshi`、`sunlaoshi`（辅导员）。**初始密码均为 `123456`**。

数据覆盖三个学院、多种学生状态、各类审批状态及就业去向。姓名、单位和联系方式均为虚构演示内容，不填写身份证号码。日期相对执行当天生成。

档案数据只初始化条目信息，不设置不存在的下载路径；可在档案编辑页上传实际附件。初始化过程直接执行 SQL，不生成系统操作日志；此后的业务操作仍正常记录日志。

## 结构与历史资料

六张表为 `sys_user`、`student`、`student_record`、`work_record`、`visitor_log`、`operation_log`。学生逻辑删除保留历史业务记录。

程序及测试使用的无重置结构副本在 `src/main/resources/db/schema.sql`；调整表结构时应与 `01_schema.sql` 同步。历史设计和回归报告位于 `docs/database/`。旧 SQL 与重置前数据已移出本目录，保存在项目 `.backups/fresh-data-时间/`，不会参与新安装。
